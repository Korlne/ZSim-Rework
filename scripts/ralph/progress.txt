## Codebase Patterns
- Frontend pages: each page module exports `renderPage(route)` returning a DOM element; pages use inline edit panels (not modals) appended to the root container with `scrollIntoView`
- Locale files (src/locales/{lang}.json) use flat key-value JSON with dot notation keys like `editor.<page>.<camelCaseKey>`
- Tauri v2 `.setup()` hook takes `|app| Ok(())` closure and runs before any commands
- rusqlite: always use `bundled` feature to avoid requiring system SQLite install
- Always use `PRAGMA foreign_keys = ON;` after opening each rusqlite Connection
- SQLite schema: use `CREATE TABLE IF NOT EXISTS` for idempotent init + `schema_version` table for migrations
- data_entry module: declare `mod data_entry;` in lib.rs, sub-modules in `data_entry/` directory
- Tauri commands: `#[tauri::command]` in lib.rs, registered via `generate_handler![]`, state via `app.manage()` with `Mutex<T>`
- CSV import: calamine crate for XLSX parsing in src-tauri/src/data_entry/csv_import.rs
- Auto-import on first startup: scans data/characters/, data/equipment/, data/wengine/ for .csv/.xlsx files in order: characters → drive discs → w-engines
- i18n system: t(key, params) in src/i18n.js, flat key-value JSON in src/locales/{lang}.json, data-i18n DOM attributes for static HTML, "langchange" custom event for dynamic re-render
- When modifying lib.rs, always run `cargo check` from the repo root (Cargo.toml location)
