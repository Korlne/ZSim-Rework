## Codebase Patterns
- Frontend pages: each page module exports `renderPage(route)` returning a DOM element; pages use inline edit panels (not modals) appended to the root container with `scrollIntoView`
- Shared components: place reusable UI in `src/editor/components/`, utility functions in `src/editor/utils/`
- Frontend validation: use `src/editor/utils/validation.js` (validateCharId, validateLevel, validateCritRate, validateNonNegative, validateForm)
- Number formatting: use `src/editor/utils/format.js` (formatStat for table display, formatFixed for precision)
- SQLite schema: use `CREATE TABLE IF NOT EXISTS` for idempotent init + `schema_version` table for migrations
- rusqlite: always use `bundled` feature to avoid requiring system SQLite install
- data_entry module: declare `mod data_entry;` in lib.rs, sub-modules in `data_entry/` directory
- Cascade deletes: use `ON DELETE CASCADE` in FK definitions + `PRAGMA foreign_keys = ON;`
- JSON in SQLite: store complex nested data as TEXT columns, parse with serde_json on read
- DataLoader pattern: struct holds `rusqlite::Connection`, load methods take `&self`, complex entity reconstruction via JOINs
- Enum serialization: store enums as serde-rename strings in TEXT columns, deserialize with `serde_json::from_str(&format!("\"{}\"", value))`
- from_json_dir: embed schema + JSON import logic directly on DataLoader for self-contained bootstrap from flat files
- Editor pattern: hash-based routing (#/route) with lazy-loaded page modules via dynamic import(), sidebar with active state tracking, shared components (datatable, form, confirm) in src/editor/ root
- i18n system: t(key, params) in src/i18n.js, flat key-value JSON in src/locales/{lang}.json, data-i18n DOM attributes for static HTML, "langchange" custom event for dynamic re-render
- i18n enum translation: use i18n-maps.js (FACTION_MAP, SPECIALTY_MAP, etc.) to map raw DB values → i18n keys; keys follow pattern `enum.<category>.<snake_case_value>`; usage: `t(MAP[rawValue])`
- CSV import: calamine crate for XLSX parsing in src-tauri/src/data_entry/csv_import.rs, functions return Result<usize, String>
- Tauri commands: #[tauri::command] in lib.rs, registered via generate_handler![], state managed via app.manage() with Mutex<T> for interior mutability
- Simulation: run_simulation spawns std::thread with app.clone() to emit progress events, SimulationState with Arc<AtomicBool> for cancellation, config passed as JSON string
- Tauri setup hook: use `.setup(move |_app| { ... Ok(()) })` for startup tasks (auto-import, etc.); runs before any commands; clone PathBuf if you also need it for managed state
