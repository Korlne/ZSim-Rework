## Codebase Patterns
- ElementTag is a fieldless enum, derive Copy + Clone to avoid unnecessary .clone() calls.
- AnomalyDisorderManager pattern: `states: HashMap<String, Vec<AnomalyState>>` per-enemy, lazy-slot-creation per element. Borrow split trick: read gauge in a block, drop mutable borrow, then call &self methods before resuming mutation.
- AnomalyState stores `gauge_at_trigger` for disorder damage calculations. If the new element has no AnomalyState slot yet, gauge is treated as 0.0 for disorder calcs.
- AccumulateResult/TriggerAnomalyResult/DisorderResult structs provide structured feedback without coupling to the event bus.
- Ralph tracking files are at `scripts/ralph/prd.json` and `scripts/ralph/progress.txt`. The `ralph/` directory at project root is a separate Claude Code plugin repo with its own `.git`.
- Rust toolchain: Always use `stable-x86_64-pc-windows-gnu` as default. The MSVC toolchain can fail when `link.exe` from Git for Windows shadows the MSVC linker, while GNU can fail when `dlltool.exe` is missing from PATH. If GNU fails with "dlltool.exe not found", try MSVC (`rustup default stable-x86_64-pc-windows-msvc` + `export PATH="$PATH:/c/Users/59275/.cargo/bin"`). `cargo test` and `cargo clippy` (without `--all-targets`) work on MSVC.
- When using `data` in a struct literal like `ActiveBuff { data, remaining_ticks: data.duration_ticks }`, read the field BEFORE the move: `let duration = data.duration_ticks; ActiveBuff { data, remaining_ticks: duration, ... }`.
- Damage calculation modules: Use unit structs with `fn calc(&self, input: &CalcInput, rng: &mut RNGManager) -> CalcOutput` signature. CalcInput has Default impl with safe defaults (res_factor=1.0, anomaly_threshold=100.0).
- Defense formula: `effective_def = (def * (1 - pen_ratio) - pen).max(0.0)` and `def_factor = 1.0 / (1.0 + effective_def / 1000.0)`.
- Anomaly damage never crits. Proficiency factor = `1 + anomaly_proficiency / 100`.
- Anomaly accumulation: `gauge_added = anomaly_mastery * multiplier`, trigger at threshold.
- Stun is deterministic (no RNG). Resources/DR also have no RNG dependency.
- EquipmentManager pattern: use `from_equipment_data()` to index disc sets into `HashMap<String, DiscSet>` for O(1) set bonus lookup. Disc set bonus resolution counts discs per set_id and checks thresholds (2-piece >= 2 discs, 4-piece >= 4 discs).
- Buff resolution via string ID: define a `resolve_buff(buff_id: &str) -> Option<BuffData>` match-based method on the manager. Unknown IDs return None and are silently skipped. This pattern is extensible as more buff IDs are added.
- EventBus pattern: use `std::sync::mpsc` channels for sync pub-sub event bus (simpler than Tokio broadcast for zero-async simulation engines). Each subscriber gets a dedicated channel. Dropping the receiver auto-cleans up.
- W-Engine base stats and Drive Disc main/sub stats should be registered as individual buffs with unique IDs to allow the BuffManager to aggregate them correctly.
- CoordinatedActionSystem pattern: `last_trigger_tick: Option<u64>` for per-listener cooldown — `None` means first trigger always allowed. This avoids the off-by-one bug where initializing `last_trigger_tick = 0` blocks the first trigger when cooldown > 0. Cooldown check: `current_tick < last + cooldown_ticks`, skip if `None`.
- CoordinatedListener trait with `Debug` supertrait makes `Box<dyn CoordinatedListener>` implement `Debug` automatically (vtable dispatch).
- Parquet writer pattern: `ArrowWriter::flush()` creates row-group boundaries. `Compression::ZSTD` takes `ZstdLevel` (newtype), not `Option<i32>`, in parquet 55. Use `SerializedFileReader` for metadata row-group counts (reader merges on read).
- LoggedEvent has 6 optional extended payload fields (element, anomaly_gauge, stun_dmg, buff_id, buff_value, coordinated_flag) that can be populated as events are generated for richer Parquet output.
- zsim-parquet crate depends on zsim-core for type access (SimResult, LoggedEvent, EventType).
- ParquetAggregator pattern: unit struct with `aggregate(path, &AggQuery) -> AggResult`. Each of 7 query types has a dedicated private function. Batch iteration over all row groups with in-memory event_type filtering. StatsSummary uses Welford's online algorithm for O(n) mean+variance, and R7 interpolation for percentiles.
- Tauri v2 bundle config: Use `bundle.resources` to glob-pattern data/ and scripts into the installer. Use `app.path().resource_dir()` at runtime to resolve bundled resource paths — resource_dir exists in dev mode too but with different content. For sidecar scripts (Python), resolve via `resource_dir().join("analysis_sidecar.py")` with CWD fallback for development.
- Multi-platform bundle targets: `tauri.conf.json` `bundle.targets` can be `["nsis", "msi", "appimage", "deb", "dmg"]` — each platform uses only its applicable targets. Tauri auto-downloads WiX for MSI and uses system NSIS for NSIS installer. Icon requirements: Tauri v2 needs 32x32.png, 128x128.png, 128x128@2x.png, icon.ico, icon.icns (minimal set).
