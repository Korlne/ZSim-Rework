## Codebase Patterns
- Tauri v2 on Windows: `icons/icon.ico` is required by `tauri-build` even for `cargo check` — a minimal valid ICO can be generated from raw BGRA pixel bytes via Python `struct.pack`
- Tauri v2 uses `tauri-plugin-shell` for sidecar (not the v1 `tauri::api::process::Command`)
- Tauri v2 commands: define `#[tauri::command] fn` in `lib.rs`, register via `generate_handler![]`, manage state with `app.manage()` + `app.state::<T>()`
- Vite + Vanilla JS is the minimal frontend setup: `vite.config.js`, `index.html` at root, JS in `src/`
- `src-tauri/` can be a Rust workspace member without conflicts on Windows
- Sidecar processes: manage via `tauri::State` with `Mutex<Option<Child>>` + `Mutex<Option<ChildStdin>>`
- **Import module pattern**: Each data type has its own `import_<type>()` function in `import.rs`. They take `&Connection` and `data_dir: &Path`, return `ImportResult { success, errors }`. Use zsim-core's existing entity structs for JSON deserialization (they already have correct serde annotations for the data files). Convert enums to strings via `serde_json::to_value()` + `as_str()`. Store complex nested data (constellations, resistances, tracks) as JSON TEXT in SQLite. Use `INSERT OR REPLACE` for idempotent reimport.
- **Data entry Tauri commands**: DataDirState (managed via `.manage(DataDirState { data_dir })`) shares the data directory path across all data entry commands. Access via `State<'_, DataDirState>` parameter. Open a fresh `rusqlite::Connection` per command for infrequent ops (init, import). Always enable `PRAGMA foreign_keys = ON;` after opening each connection. Define commands directly in `lib.rs` and register in `generate_handler![]`.
